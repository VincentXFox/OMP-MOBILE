# Граф памяти

Второй слой памяти рядом с Mnemopi. Mnemopi отвечает на вопрос «что я знаю про этого человека и этот проект вообще» — личные факты, эпизоды, гисты. Граф отвечает на другой: **«что мы уже решили по этому проекту, почему и когда это проверяли»**, и делает это проверяемо: у каждого утверждения есть дата, проект и сессия-источник.

## Зачем отдельный слой

- Транскрипты сессий — единственный источник, где решения записаны вместе с причиной («оказалось, причина в Alt-Svc на h3»), но читать их заново дорого.
- Обычный recall по эмбеддингам смешивает болтовню с решениями и не даёт провенанса.
- Утверждение с датой и источником можно проверить и оспорить; «похожий текст» — нельзя.

Mnemopi остаётся как есть: граф ничего не перезаписывает и не подменяет.

## Как устроено

```
транскрипты  →  extract  →  store (SQLite)  →  retrieve  →  контекст агента
~/.omp/agent/    правила      facts + nodes     ранжирование   хук graph-memory
sessions/*.jsonl  смысла      + провенанс       по 4 сигналам   (before_agent_start)
```

### Экстракция (`gateway/memory-graph/extract.ts`)

Точность важнее полноты: в граф попадает только то, что не стыдно подставить в контекст.

- Утверждение обязано иметь **маркер смысла** — решение, причину, исправление, правило или ошибку; иначе это болтовня.
- Нужна хотя бы одна **сущность**: путь, файл, юнит, хост, инструмент, проект.
- Код, таблицы, диффы и строки команд отбрасываются: в графе должны быть утверждения, а не фрагменты кода.
- Одна и та же фраза, повторённая в тексте или в разных сессиях, — один факт с счётчиком упоминаний.

Виды фактов: `decision`, `insight`, `fix`, `rule`, `error`, `fact`. У каждого сохраняются `confidence`, `importance`, `first_seen`, `last_seen`, `session_id`, `quote`.

### Хранилище (`store.ts`)

SQLite в `~/.local/state/omp-pocket/graph-memory.db` (переопределяется `OMP_GRAPH_DB`), WAL.

| Таблица | Смысл |
|---|---|
| `facts` | утверждение + нормализованный текст (дедупликация) + провенанс + валидность (`valid_from`/`valid_to`) |
| `nodes` | сущности: проект, хост, сервис, путь, инструмент, тема |
| `indexed_files` | состояние транскриптов: инкрементальный индекс не перечитывает неизменённое |
| `meta` | служебные метки (время последней индексации) |

Факт — это ребро: `src` (сущность-подлежащее), `dst` (вторая сущность), `fact` (само утверждение). Узлы нужны для навигации «что связано с de5», рёбра — для контекста.

### Индексатор (`index.ts`)

Шлюз раз в 5 минут разбирает порцию транскриптов (25 файлов, бюджет 4 с) — полный проход не должен задерживать ход шлюза. Полная перестройка: `POST /api/graph/rebuild` (на 260 файлах и 300 МБ истории — около 4 секунд).

### Ранжирование (`retrieve.ts`)

Оценка факта = `0.42·лексика + 0.28·свежесть + 0.18·важность + 0.12·упоминания + 0.02·уверенность`, умноженная на релевантность проекта.

- Лексика — доля слов запроса, найденных в факте (стемминга нет: дешёво и предсказуемо).
- Свежесть — экспонента с периодом полураспада 45 дней.
- Проект: точное совпадение каталога — 1.0, подпроект — 0.9, **родитель — 0.6** (сессии часто живут в `~`, а проект — `~/omp-mobile`), чужой проект — 0 (не подмешивается).

Контекстный блок — до 1400 символов (900 в хуке), пункты вида `- [решение] текст (проект, дата)`.

## API

| Метод | Что делает |
|---|---|
| `GET /api/graph/stats?project=<cwd>` | счётчики фактов/узлов/проектов, разбивка по видам, время индексации, топ-узлы проекта |
| `GET /api/graph/search?q=&project=&limit=` | ранжированные факты с `score` и `matched` |
| `GET /api/graph/context?project=&q=&maxChars=` | готовый текстовый блок для контекста |
| `GET /api/graph/nodes?project=` | узлы проекта по упоминаниям |
| `POST /api/graph/rebuild` | пересобрать граф с нуля |

Все маршруты требуют Bearer-токен шлюза, как и остальное API.

## Инъекция в агента

Хук `~/.omp/agent/hooks/pre/graph-memory.ts` на `before_agent_start` читает базу **только на чтение** и добавляет в системный промпт один блок `<<<GRAPH-MEMORY …>>>`:

- не меньше 3 пунктов, иначе блок не добавляется;
- тот же блок повторно в той же сессии не инжектится (сравнение по sha256);
- базовый системный промпт сохраняется;
- любая ошибка — fail-open: агент стартует без блока, а не падает;
- источник помечен как недоверенный: это цитаты из прошлых сессий, а не инструкции.

## Проверки

```bash
cd gateway && bun test tests/graph-*.node.test.ts   # экстракция, хранилище, ранжирование
bash ~/.omp/agent/hooks/tests/gm-regression.sh      # хук: инъекция, сохранение базы, дедупликация
```

Живая проверка инъекции: `omp -p "перепиши первые пункты блока GRAPH-MEMORY"` — модель цитирует факты, а сверка с базой показывает посимвольное совпадение.

## Границы

- Экстракция детерминированная: она не «понимает» смысл, поэтому часть ценных утверждений без маркеров не попадает в граф, а часть слабых — попадает (их отсекает ранжирование).
- Дедупликация текстовая: два пересказа одного решения — два факта.
- Валидность (`valid_from`/`valid_to`) заполняется датой наблюдения; устаревание факта пока не выводится автоматически — старые факты просто опускаются ранжированием.
- Векторного поиска нет: на корпусе в сотни-тысячи фактов лексическое совпадение дешевле и объяснимее.
