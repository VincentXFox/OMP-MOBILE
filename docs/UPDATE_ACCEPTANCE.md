## Дефекты, найденные ЖИВЫМ прогоном (и исправленные)

| # | Что случилось | Причина | Исправление | Подтверждение |
|---|---|---|---|---|
| L1 | Панель после SIGTERM не поднялась: `--continue --restore` → `Error: --restore resumes one existing session` | `launchArgvOf` вырезал только `--resume/--restore`, `--continue` оставался в argv | вырезаются все одноразовые селекторы (`--continue/-c/--session/--fork/--no-session/--goal/imports`) | `recovery/tests/resume.test.ts` (новый тест), job `live-accept-4` COMPLETED |
| L2 | Проверка падала сразу после рестарта: «живых сессий 0, в чекпоинте 1» | регистрация в collab занимает секунды, а VERIFYING требовал полный набор мгновенно | VERIFYING проверяет идентичность образа у живых; полнота набора — в RESTORING (ожидание до 45 с + одна повторная попытка) | job `live-accept-4` (VERIFY ok → RESTORING restored=1) |
| L3 | Рестарт релея «восстанавливал» и будил промптами ВСЕ 33 живые сессии (включая мою рабочую) | RESTORING/RESUMING считали восстановленными все зарегистрированные сессии, а не только перезапущенные задачей | восстанавливаем и продолжаем только сессии с `recovery.killed/relaunched`; остальные не считаются и не трогаются | chaos-тест 28 + живой job `relay-1792884681336`: 0 из 36, 0 продолжено |
| L4 | «omp-local-relay в состоянии 3169852» — ложный провал проверки | позиционный разбор `systemctl show --value` (systemctl печатает `MainPID` раньше `ActiveState`) | разбор `key=value` | живой job после фикса: `relay: active, pid …, 7466 открыт` |
| L5 | Задача «herdr» упала на проверке сразу после рестарта (`herdr api snapshot: код 1`) | проверка без ожидания готовности сервера | `waitHerdrReady` с таймаутом 15–45 с во всех точках | код + chaos 28; повторный живой рестарт herdr намеренно не запускался (риск для живых панелей) |

Отдельно: 15 сессий, получивших лишний промпт из L3, были остановлены (`herdr agent send-keys … esc`); одна из них (модель
big-pc) висела на `503 Loading model` и тоже снята. Данные сессий не пострадали: 36 живых сессий после инцидента.

## Что осталось непроверенным (честно)

- Реальная перезагрузка Ubuntu в середине обновления — эмулировалась SIGKILL оркестратора в 7 фазах (chaos 6), сам ребут не
  выполнялся (прервал бы живые сессии пользователя). `[физически-нет]`
- Реальный разрыв сети телефона во время апдейта — серверная часть проверена (прогресс на диске, chaos 5/16), мобильный
  клиент на устройстве не проверялся. `[физически-нет]`
- Повторный живой прогон рестарта `herdr-server` после фикса L5 — не выполнялся, чтобы не дёргать панели; покрыто кодом и chaos. `[нужно-согласие]`
- Миграции БД — в gateway их нет, сценарий неприменим.

## Риски, которые остаются

- `pi-wire` приложения 18.10.3 против omp 18.12.6 — UI показывает предупреждение о возможном отличии протокола collab;
  обновление фронтенда под 18.12.x не входило в этот этап.
- Продолжение турна после `--restore` для SIGTERM-пути делает промпт модели: гарантия «проверь результат» — инструкция, а не
  механическая блокировка повтора опасной операции. Для необратимых действий по-прежнему нужен человек.
- Частичное применение (`--only`) фильтрует по подстроке пути — при совпадении подстроки возможен лишний рестарт.
- Обновление кода требует чистого рабочего дерева: с грязным деревом задача честно уходит в `BLOCKED`.

## Итог

Механика «нажал Обновить → новая версия работает → сессия восстановлена → задача продолжена» подтверждена на живом стенде:
деплой нового движка, запуск задачи из PWA, отсутствие влияния на чужие сессии, продолжение реальной прерванной задачи.
Пять дефектов, найденных живыми прогонами, исправлены и покрыты регрессиями.
