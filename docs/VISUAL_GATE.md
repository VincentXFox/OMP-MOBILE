# Визуальная приёмка (visual-gate)

Машинная приёмка интерфейса: не одна «общая картинка», а серия снимков и два независимых разбора.

## Что снимается

- Каждый маршрут × каждый размер окна × три положения прокрутки (верх, середина, низ) — так видны реальные экраны, а не склеенное полотно.
- Крупный план каждой значимой детали (`--details`): карточка, заголовок, строка настроек; элемент прокручивается в центр, снимок берётся по актуальному прямоугольнику.

## Как анализируется

1. **Геометрия в странице:** горизонтальный выхлоп, элементы за правым краем, перекрытия интерактивных элементов в потоке (накрытие фиксированными барами — это хром, а не дефект), цели нажатия меньше 28×24.
2. **Vision-модель:** каждая картинка уходит дешёвой vision-модели cheapference (`gpt-5.6-luna`, 0.08/0.48 за млн токенов) со строгим промптом: только наложения в потоке, обрезанный внутри карточки текст, сломанное выравнивание, пустые блоки с рамкой. Прокрутка, фиксированные панели и «частично видимый элемент у края» дефектом не считаются. Если облако недоступно — локальная Qwen3-VL на 127.0.0.1:8080.

## Запуск

```bash
bun bin/visual-gate.ts run --plan .omp/visual/plan.json --out /tmp/omp-visual
# код 0 — дефектов нет, 1 — найдены; report.json/report.md и снимки в --out
```

План: `{"url","token","routes":[…],"viewports":[{name,width,height}],"details":[{route,selector,name}]}`.
Секретный `token` в план не коммитится (`.omp/visual/` в `.gitignore`).

## Приёмка гейта самого себя

Негативный контроль: `fixture` с тремя подложенными дефектами (наложение кнопок, обрезанный текст, пустой блок с рамкой) — найдены все: 6 дефектов на 3 снимках. На рабочем Pocket 84 снимка → 0 дефектов.

## Встраивание в контракт

Визуальный прогон ставится обычной проверкой, и её воспроизводит независимый верификатор (`omp-verifier`, Chrome с `--no-sandbox`, снимки в `/tmp`):

```bash
--check "визуал::bun bin/visual-gate.ts run --plan .omp/visual/plan.json --out /tmp/omp-visual"
```
