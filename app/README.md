# @oh-my-pi/collab-web

Web client for [omp collab sessions](../../docs/collab.md). Paste a `/collab` link into the browser and you get the same live session guests see in the TUI: streaming transcript, tool-call cards, subagent panel with live transcripts, and a composer that prompts (or interrupts) the host agent.

## Quick start

```sh
# dev server (Bun HTML dev server with HMR) — http://localhost:3000
bun run dev

# offline demo: local relay + scripted mock host; prints a ws://localhost link
bun run mock-host
```

Host a session from any omp instance (`/collab`, or `/collab ws://localhost:7466` to use the mock relay), then paste the printed link into the connect screen. Deep links work too: `http://localhost:3000/#<roomId>.<key>` auto-connects on load.

## Build & deploy

```sh
bun run build   # static site in dist/
```

`dist/` is a fully static SPA — host it anywhere. JS/CSS bundles are content-hashed; favicons, `manifest.webmanifest`, `robots.txt`, `sitemap.xml`, and `og-image.png` come from `public/` and are emitted at the site root under stable names (canonical URL: `https://my.omp.sh/`). Two runtime requirements:

- **Secure context**: room keys are unwrapped with WebCrypto (`crypto.subtle`), which browsers expose only on `https://` or `localhost`.
- **Relay reachability**: the client connects straight to the relay over WebSocket (`wss://` for anything that isn't localhost). The default relay is `wss://my.omp.sh`; bare `<roomId>.<key>` links resolve against it (legacy `<roomId>#<key>` and `%23`-mangled links still parse).

The room key never leaves the URL fragment — it is not sent to the relay or any server.

## Architecture

- `src/lib/` — vendored wire codec (`codec.ts` AES-256-GCM, `link.ts` envelope + link grammar), `socket.ts` reconnecting relay socket, `client.ts` guest session store (`GuestClient` + immutable snapshots for `useSyncExternalStore`). Shared protocol shapes come from `@oh-my-pi/pi-wire`.
- `src/components/` — `transcript/` (entries, markdown, tool cards), `agents/` (panel + transcript drawer), `shell/` (connect screen, header, composer, banners, toasts).
- `src/tool-render/` — per-tool React renderers shared with coding-agent HTML session exports: one view per built-in tool, common `ToolView` chrome, theme-adaptive `tv-` design tokens, and an `<omp-tool-view>` web-component wrapper. The `ToolRenderHost` seam lets hosts wire agent-id chips to a sub-session view (drawer here, overlay in exports).
- `scripts/` — `local-relay.ts` (content-blind relay on `Bun.serve`), `mock-host.ts` + `fixture.ts` (scripted host for offline dev), `build-tool-views.ts` (bundles `src/tool-render/` + React into `packages/coding-agent/src/export/html/tool-views.generated.js` for self-contained exports).

The package is intentionally standalone — no dependency on `@oh-my-pi/pi-coding-agent` at runtime or type level. Wire-shape drift is prevented by consuming the same `@oh-my-pi/pi-wire` contracts as the host, with sealed-frame interop still covered by `test/codec.test.ts`.

## Автоворестор, имена, туду (2026-10-14)

**Восстановление после сбоя питания.** Шлюз на каждом опросе реестра пишeт `gateway/runtime-manifest.json` (какие omp-сессии должны жить: sessionId, cwd, модель, имя). При старте шлюза `gateway/restore.ts` ждёт реестр и поднимает каждую жертву через `omp --restore` (доделывает прерванный ход и перезапускает субагентов), затем добирает осиротевшие панели рантайма (omp-агенты без живого хоста — свежайший `interrupted/aborted`-файл их cwd). Старые instanceId маппятся на новые (`restore-remap.json`, маршрут `/api/sessions/remap`). Приложение: упавший чат сам ищет хост с тем же sessionId и переоткрывается; устаревший `#/session/<id>` проходит ремап в `openInstance`.

**Имена.** Пользовательская кириллица переживает всё: `POST /api/sessions/rename` и rename агента пишут официальный 256-байтовый title-слот omp (in-place, `source:"user"`, + audit-строка `title_change`) и хранят имя в `gateway/agent-names.json` по стабильному sessionId. `HostInfo.displayName` идёт с шлюза; имя панели остаётся служебным. Без title имя сессии = первый пользовательский запрос (preview), не UUID.

**Список сессий.** Показывается дата создания (из имени файла) + свежая активность; форки/сиблинги (`parentSession` в header) помечены чипом «продолжение»; `прерван/прерван при сбое` поднимается кнопкой «Поднять с доделкой» (`--restore`), остальные — обычный resume.

**Туду всегда перед глазами.** `lib/todo-board.ts` достаёт последний `todo`-результат из транскрипта (details.phases), `TodoBar` липнет над композером: N/M, прогресс, текущая фаза, тап — полный борд.

## Супер-раздача по плану + CLI-мост (2026-10-14)

**Режимы раздачи в «Супер-агенте».** Переключатель «Всем одинаково / По плану»: прежний broadcast без изменений; в режиме «По плану» каждый выбранный агент получает свою карточку с задачей (черновики per-agent переживают снятие выбора и переключение режима). Валидация до POST: непустой текст у каждого выбранного (подсказка с именами), ≤12 агентов, ≤64 КиБ на текст (лимиты gateway). Отправка — снапшот текстов; после результатов очищаются только успешно отправленные и неизменённые за время полёта. Любая правка компоуза (текст/режим/выбор) сбрасывает показ результатов — подсказки валидации не глушатся старым ✓/✗.

**CLI для OMP-сессий.** `bin/super-dispatch.ts` — супер-чат сам читает доску и раздаёт задачи воркерам, не выходя из своей сессии: `board` (таблица target/имя/статус/модель/cwd, read-only), `send <target> <файл|->` (одна задача, текст из файла/stdin через JSON, pre-check 64 КиБ), `activity <target>` (статус, хвост терминала, субагенты). Конфиг — `gateway/config.json` (`SUPER_GATEWAY_CONFIG` перекрывает), токен не печатается никогда. Exit-коды: 0 ок, 1 ошибка API/агента, 2 нет конфига, 3 шлюз недоступен, 4 401, 5 плохой ввод. Пример: `bun bin/super-dispatch.ts send w1:p1 task-algol.md`.

## Выбор модели и живое подключение (2026-10-16)

**Модель теперь выбирается, а не набирается.** `GET /api/models` (шлюз, каталог `omp models ls --json` с кэшем 10 мин и stale-on-error) кормит общий лист `shell/ModelPickerSheet`: поиск по провайдеру/id/имени, группировка по провайдеру, контекст и уровни усилия в строке. «Новый агент» открывает его по кнопке «Модель» (последний выбор запоминается в `localStorage`, пункт «По умолчанию» = модель из настроек omp), чат — по тапу на чип модели в композере и строкой «Сменить модель и усилие» в «Об агенте».

**Смена модели живого чата — клавишами в TUI агента** (`GET/POST /api/agents/<id>/settings`). Прежняя реализация собирала `/model <селектор>` одним залпом и отправляла это сообщением в чат: `/model` открывает интерактивный пикер, поэтому текст уходил агенту как промпт («Unknown model» не наступал, модель не менялась). Теперь шлюз ведёт диалог по шагам и сверяет экран панели после каждого: `/` → `model` → пикер открыт → поиск полного селектора → `Enter` (полоса ролей `… → [ default ] …`) → `Enter` (роль) → `Enter` (уровень усилия) → `Esc` до закрытия пикера. Каждый шаг подтверждается фрагментом чужого экрана, поэтому при расхождении возвращается ошибка, а не молча испорченный чат.

**Уровень усилия** — отдельный флоу `/effort`: стрелками до нужной подсветки, `Enter`. Текущее значение читается из статус-строки панели: omp v18.10.4 печатает глиф перед моделью (`⦸ off · ⟳ auto · ◔ low · ◒ high · ◉ max`); прежний парсер ждал «Thinking set to …» из старых версий и всегда возвращал null. Глиф-маппинг снят вживую.

**Esc не шлётся вслепую.** В чистом композере omp `Esc` — это rewind сессии, а под работающим агентом — прерывание хода. Поэтому: смена настроек запрещена, пока агент занят или ждёт подтверждения (и в API, и в UI), меню закрываются по состоянию экрана, остатки ввода убираются backspace'ами.

**Возврат в приложение.** `visibilitychange`/`online`/`pageshow` → `GuestClient.reconnectNow()` (сброс backoff сокета, новый сокет за ~300 мс, свежий welcome со снапшотом; дубли пары событий гасятся троттлингом). Поллинг `/api/hosts` останавливается в скрытой вкладке и обновляется сразу при возврате — телефон не жжёт батарею в фоне. В баннере «Переподключение…» есть кнопка «Сейчас». Фаза `live` теперь пишется «На связи» (прежнее «Работает…» врало у простаивающего агента), а карточка агента в момент открытия показывает «Открываю…» — тап больше не выглядит потерянным.

## Хаб агентов: секции, поиск, закрепление (2026-10-16)

**Почему.** Два десятка сессий лежали одним списком: имена проектов обрезались до «vincen…», сортировка шла по статусу — работающий агент прыгал наверх при каждом изменении хода («агенты перемешиваются»), «21 ч назад» стояло у всех одинаково, поиска и фильтра не было. Плюс четыре сессии вообще были безымянными: реестр `omp collab list` даёт имя только на момент старта и ничего не знает о сессиях без панели.

**Секции вместо мешка** (`components/agents/AgentsScreen.tsx`): «Закреплённые» → «Ждут ответа» → «Работают» → «На паузе» → «Черновики и эксперименты» (`/tmp`, свёрнуты) → «Спят и без связи» (нет процесса/релея). Внутри секции сортировка по последнему открытию (карта `sessionId → ts` в `localStorage`, `lib/agent-prefs.ts`), а не по статусу: список больше не перетасовывается, а агент, которому нужно действие, не прячется под свёрнутой секцией. Свёрнутость секций помнится; при активном поиске всё раскрывается.

**Поиск и закрепление.** Полоса поиска (имя/путь/модель/имя сессии) липнет под шапкой, сверху — сводка «N агентов · M работают · K ждут ответа». Звезда на карточке закрепляет агента наверху; и закрепление, и «недавние» хранятся по `sessionId` — это переживает перезапуск сессии, сбой питания и remap `instanceId` в шлюзе.

**Карточка.** Имя в две строки, кромка цвета проекта (палитра по алфавиту папок — одинаковый цвет = один проект, столкновений у двух разных папок нет), абсолютное время запуска («вчера 22:52» вместо «21 ч назад»), шильдики «черновик» и «+2 субагента» (из доски «Роя»), «Работает 1 ч 6 мин».

**Имена — одно правило на весь интерфейс** (`lib/agent-name.ts`): переименование пользователя → заголовок сессии → первый запрос → имя из реестра → короткий `sessionId`. Шлюз отдаёт `sessionTitle` (256-байтный title-слот omp из файла сессии, включая переименования из TUI) и `sessionPreview` (первый запрос); чтение заголовка кэшируется по `(путь, mtime, size)`, поэтому 5-секундный опрос реестра не перечитывает по 64 КБ на агента. Этим же правилом пользуется шапка сессии и табличка переименования — раньше после тапа карточка называлась «Почини растдекс», а сессия «vincentfox».

**Парсер превью** (`gateway/sessions.ts`) теперь понимает и `custom_message` с `attribution: "user"` («collab-prompt»): запрос, отправленный из приложения, приходит не `message`, а этим типом, из-за чего начатая с телефона сессия оставалась безымянной. Пустой title-слот («») трактуется как «имени нет» и в списке сессий: показывается первый запрос, а не UUID.

## Поиск по словам во всех сессиях (2026-10-16)

**Зачем.** «Я помню, что про Cudy писал» — а найти это можно было только глазами по списку из 141 сессии. Теперь у поля в хабе два режима: «Агенты» (по имени/проекту/модели, как раньше) и «В переписке» — полнотекстовый поиск по репликам **всех** сессий, включая мёртвые, которых в реестре уже нет.

**Индекс в шлюзе, без базы** (`gateway/session-search.ts`). Файлы сессий занимают 165 МБ, но осмысленного текста в них ~2 МБ: остальное — записи вызовов инструментов и их результаты. Поэтому в индекс идут только реплики (пользователя и ответы агента, без `thinking` и тул-вызовов), и он целиком живёт в памяти Bun-процесса: полный проход корпуса — **0.7–1.3 с**, прогрев при старте шлюза (`[search] индекс сессий: 141 сессий, 8403 реплик за 729 мс`). Обновление инкрементальное по `(mtime, size)`: перечитываются только изменённые файлы, ответ — за 1–30 мс. Строки-кандидаты отбираются подстрокой (`"type":"message"`, `custom_message` + `attribution:user`) **до** `JSON.parse` — вызовы инструментов, которых большинство в файле, не разбираются вовсе. Транскрипты субагентов не индексируются: их «пользовательские» реплики — это задания родительского агента, а не слова человека.

**Два уровня совпадения.** Сильный: все слова запроса в одной реплике («Cudy роутер» рядом) — такие результаты идут первыми и называются «слова рядом». Слабый: слова нашлись в разных репликах одной сессии («где я вообще про это писал»), показывается «слова в разных репликах»; в слабый попадают только сессии, где встретились **все** слова — иначе это шум. Сравнение — подстрока без регистра (`norm` в нижнем регистре, потому что SQLite-free LIKE по кириллице регистр не гасит), поэтому падеж и порядок слов не мешают.

**Что видно и куда идти.** Карточка результата: имя сессии, проект, число совпавших реплик, время последнего совпадения, до трёх отрывков с подсветкой (`<mark>` по смещению, которое отдал шлюз: индексы берутся из нормализованного текста, а вырезается оригинал — регистр автора сохраняется) и роль реплики («я» / «агент»). Переключатель «только мои сообщения» (по умолчанию) против «всё, что говорили». Тап по карточке: сессия живая — открывается чат; мёртвая или вовсе не в реестре — шит возобновления (в него передаётся синтетический хост: `cwd` + путь к файлу сессии, `mode: resume` — без доделки прерванного хода).

**Доопрашивание индекса.** `status.pendingFiles` в ответе говорит, сколько файлов ещё не прочитано (первый холодный запрос при незавершённом прогреве): пока он больше нуля, клиент повторяет запрос каждые 1.5 с и пишет «дочитываю N файлов», иначе пользователь принял бы неполный результат за «ничего не найдено».

## Раздел «Память»: разделы, сортировки, фильтры (2026-10-16)

**Что было не так.** Пять таблиц Mnemopi лежали равноправными вкладками, хотя ценность у них разная: `working_memory` (что агент решил сохранить) и `episodic_memory` (итоги сессий) — содержание, `facts` — машинные тройки, а `gists` и `annotations` — служебный слой (обрезки строк вида «Привет» и метаданные `occurred_on`/`has_source`). Сортировка была только по времени, фильтров не было, банков в шапке — 40 подряд (тестовые прогоны оставляют по банку на запуск), важность и уверенность печатались словами, а «гист» и его эпизод выглядели как независимые записи.

**Разделы и служебный слой.** Вкладки: «Память 177» / «Факты 905» / «Эпизоды 26» / «Всё 1488» + «Служебное 380» пунктиром, внутри — «Гисты» и «Аннотации» с пояснением, что это за данные. У каждого раздела строка-объяснение (что это и откуда). Банки: только непустые, первые шесть + «ещё 29»; хвост-хэш имени убран в `title`, а выбранный банк остаётся в ряду, даже если он дальше шестого. Сводка банка — «1488 записей · 10.9 МБ · обновлено 45 мин назад».

**Сортировки и фильтры.** `?sort=ts|importance|recall|confidence` (шлюз применяет по колонке раздела, `NULLS LAST`): у памяти «Свежие / Важные / Вспоминаемые», у фактов «Свежие / Уверенные». Фильтры — чипы источников и видов с частотами (`/facets`, `GROUP BY`), у каждого своя сортировка. При `sort=ts` список бьётся на группы «Сегодня / Вчера / 16 октября».

**Карточки.** Память: дата, вид, источник (префикс `coding-agent-` срезан: «retain», «transcript»), шкала важности (полоска + «важно/средне/слабо» вместо текста), полный текст с раскрытием, «выжимка» из `gists` прямо в карточке эпизода, а в подвале — `occurred_on`/`has_source` и «вспомянуто ×N». Факт: утверждение крупно, вид и шкала уверенности. Гист и аннотация — плотные служебные строки с началом родительской записи и кнопкой «из записи»: она переключает раздел и ищет родителя по его тексту (Mnemopi ссылается только на id, а поиск идёт по содержимому).

**Поиск.** `?type=all` — сразу по всем пяти таблицам, результаты с метками разделов: в конкретном разделе при пустом результате предлагается «искать везде» (12 записей в «Памяти» против 23 по всей памяти для «RustDesk»). Совпадения подсвечиваются, регистр не важен, запрос в строке отбора укорачивается до 40 символов.

**Чистка текста.** Разметка протокола (`[user:start]`, `[toolCall]`, метки источников) снимается, но только по закрытому списку тегов: прежнее правило `<[a-z]…>` съедало реальные плейсхолдеры (`/s/<token>/ios` превращалось в `/s//ios`).

**Шлюз.** `memory.ts`: единый `TableSpec` на таблицу (колонки, время, поиск, источник, вид, оценки), общий билдер условий, батч-обогащение страницы (аннотации и гист — по одному запросу `IN (…)` на страницу, а не на запись), режим `type=all`, `/facets`.

## Штат: папки агентов и «кто за что отвечает» (2026-10-17)

**Что было не так.** Сессии omp хранятся по рабочему каталогу, а «Новый агент» по умолчанию подставлял первый каталог из списка — домашний. Два десятка совершенно разных агентов (Cudy, дизайн PWA, память, прокси, QR-каналы) сидели в `~`, делили один цвет проекта и одинаковую подпись «vincen…», а ответить на вопрос «этот агент вообще за что?» было нечем. Проверка на живом реестре: **20 из 31 агента — в домашнем каталоге**, ещё 7 — в `/tmp/omp-pocket-scratch`.

**Стол = папка + ответственность.** `gateway/crew.ts` держит штат: каталог `~/OMP/<slug>/`, устав `AGENTS.md` (нативный файл правил omp — сессия, стартующая в папке, читает его сама, никаких лишних флагов в запуске), журнал `JOURNAL.md`, индекс `~/OMP/CREW.md` и реестр `gateway/crew.json`. Единица владения — папка, а привязка идёт по `sessionId`: `instanceId` умирает вместе с процессом, а «кто за что» — нет. Каталоги, заведённые руками, принимаются в реестр при первом обращении (`assignedBy: "adopted"`), а не игнорируются.

**Свалка — не рабочее место.** `POST /api/agents/start` больше не запускает агента в `~`, `/` или `/tmp`: `resolveDeskForStart` заводит (или переиспользует) стол, стартует сессию в его папке и привязывает её к столу. Занятый каталог проекта (`~/omp-mobile`) остаётся как есть — проект это не свалка. То же и для resume: у закреплённой сессии продолжатель поднимается в её папке, а не в общей куче. Если запуск не удался, свежезаведённый пустой стол убирается (`pruneEmptyDesk` не трогает ничего, кроме наших же `AGENTS.md`/`JOURNAL.md`).

**Организатор: раз в сутки.** `gateway/organizer.ts` собирает дижест агентов, чья папка — дом или `/tmp` (до 40), отдаёт его модели через `omp -p` (решение — «какой стол за что отвечает», группировка по темам) и применяет план детерминированно: каталоги, устав, привязки, `CREW.md`. Модель не имеет права двигать чужие файлы — она только решает. Бюджет: `--max-time 480`, JS-таймаут 600 с (на 180 с модель не успевала ответить, проверили живьём). Модель — `OMP_POCKET_ORGANIZER_MODEL` или флаг `--model`; по умолчанию модель omp. Модель недоступна или план не разобрался — работает честное правило «один агент = один стол» с ролью из заголовка сессии, а не «ничего не делать». Прогон идемпотентен, параллельные вызовы гасятся lock-файлом `~/OMP/.organizer.lock` (шлюз и таймер — разные процессы), пустые столы-заглушки после переезда агентов убираются.

**Расписание и запуск руками.** `deploy/omp-pocket-organizer.{service,timer}` — user-таймер на 04:00 (`Persistent=true`: пропущенный при выключенном ноутбуке прогон делается при первом включении). Ручной прогон: `POST /api/crew/organize` (шлюз отвечает 202, прогресс виден в `/api/crew` → `organizer.running`) или `bun bin/organizer.ts run [--dry-run] [--model X]`; `bin/organizer.ts status` показывает последний прогон, следующий по расписанию и список столов. Итог прогона уходит пуш-уведомлением и строкой в `~/OMP/organizer.md`.

**Что видно в приложении.** На карточке агента — чип роли стола («Сеть, роутеры и прокси»), роль ищется строкой поиска. В шапке хаба — чип «Штат» (`components/crew/CrewSheet.tsx`): корень штата, состояние организатора (режим, когда был, когда следующая), кнопка «Разложить сейчас», по карточке на стол — роль, зона, путь и агенты, плюс предупреждение «N агентов сидят в общих папках», когда раскладывать есть что. В «Новом агенте» появилось поле «За что отвечает» с честным пояснением: при пути-доме агент получит свой стол, роль можно не заполнять — её определит суточный организатор.

**Чего сознательно нет.** Работающий агент не переезжает: cwd процесса не меняется на ходу. Стол применяется при следующем старте/resume — об этом говорит и текст в интерфейсе. Сессии, лежащие в настоящих каталогах проектов, организатор не трогает: он разбирает свалку, а не переписывает проекты.

## Промпты AI-инструментов: библиотека уставов (2026-10-17)

**Что подключено.** Публичный репозиторий `x1xhlol/system-prompts-and-models-of-ai-tools` (GPL-3.0) — 111 файлов по 31 инструменту, от Cursor и Windsurf до Devin, v0, Claude Code, Xcode и Comet. Это не скилы, а **уставы**: готовый системный промпт инструмента можно поставить уставом стола, и агент начнёт работать в его характере.

**Шлюз.** `gateway/prompts.ts` индексирует локальный клон `~/prompts/ai-tools-prompts` (обход на два уровня, `.txt/.json/.md`, README/LICENSE исключены) и ищет по названию и по содержимому с отрывком совпадения: `GET /api/prompts?q=&tool=`, `GET /api/prompts/<id>` (до 200 КБ). Индекс — TTL 60 с, тексты кэшируются по mtime, никаких сетевых вызовов на запрос. `id` — относительный путь внутри библиотеки; на чтении он сверяется с индексом и приводится к абсолютному с проверкой префикса, поэтому `../` из запроса ничего не достаёт.

**Шит «Промпты»** (`components/prompts/PromptsSheet.tsx`, чип в шапке хаба рядом со «Штатом»): поиск, фильтр чипами по инструментам (31 штука — одна прокручиваемая строка, не перенос), карточки с первыми строками, на выбранном файле — моноширинный просмотр и две кнопки. «Стол по промпту» заводит стол `~/OMP/<slug>` (роль = название промпта), пишет промпт в `AGENTS.md` и стартует там агента — дальше это обычный стол штата, который переживает суточную синхронизацию (устав лежит в ручной части файла, источник записан как `charterSource` в реестре). «Копировать» — в буфер обмена.

**Цена.** Устав уходит в системный промпт каждого хода: 38 КБ (Cursor Agent 2.0) — это ~10k токенов, самый большой файл библиотеки (`Claude Fable 5`, 120 КБ) — ~30k. Поэтому размер показан до запуска, а старт с уставом больше 200 КБ шлюз отклоняет (413) — это уже свалка, а не характер.

## Дизайн для ПК (2026-10-24)

Раньше брейкпоинтов не было вообще: только мобильная раскладка с нижней навигацией,
поэтому на широком экране интерфейс оставался узкой телефонной колонкой, а экран
сессии был `position: fixed` и закрывал собой всё.

Что добавилось — один слой `src/styles/desktop.css`, импортируется из `app.tsx`
после `pocket.css`. Всё живёт внутри `@media (min-width: 1024px)` и
`@media (min-width: 1500px)`; мобильная раскладка не меняется.

| элемент | телефон | ПК (≥1024) |
|---|---|---|
| навигация | нижняя панель | левый сайдбар 248 px (272 px на ≥1500), иконка + подпись, активный пункт с подложкой |
| шапка | центр, 44 px кнопки | верхняя панель 60 px: заголовок слева, статус сети справа |
| контент | полная ширина | колонка `max-width: 1180 px` по центру, телефонный потолок 640 px снят |
| карточки агентов | один столбец | сетка `auto-fill minmax(360px, 1fr)` внутри секции |
| экран сессии | `position: fixed`, на весь экран | внутри оболочки: сайдбар виден, транскрипт и композер ограничены 900 px и центрированы |
| шторки | нижний лист | диалог 560 px по центру |
| FAB | над нижней панелью | в углу контента, снизу добавлен отступ 96 px |

Навигация теперь рендерится всегда (раньше `screen !== "session"`), на телефоне её
скрывает `.pk-nav--hidden-mobile` в экране сессии.

Шрифтовой стек `--font-ui` получил эмодзи-фолбэк **после** generic family: если
поставить "Noto Color Emoji" раньше `sans-serif`, браузер берёт из него цифры
(они входят в emoji-шрифт как keycap) и разряжает всю типографику.

Проверено через CDP на живом шлюзе: `.ss-root` → `position: static`, высота 900;
сайдбар 248 px колонкой; строка транскрипта 900 px по центру (left 389 при окне
1440); композер 900 px (left 394); `scrollWidth` = 1440 на всех экранах — горизонта
нет; на 390 px навигация снова `position: fixed`.

## Вставка картинок из буфера (2026-10-24)

Раньше `Ctrl+V` в композере ничего не делал: у поля не было обработчика `paste`,
вложения шли только через меню «+» и file-input.

Теперь у контейнера `.ss-composer` есть `onPaste`: файлы из `clipboardData.items`
(kind `file`) уходят в тот же `pickAnyFiles`, что и меню «+» — картинки становятся
превью-вложениями, текстовые файлы и бинарники (pdf/zip) — вложениями с ссылкой в
промпте. Вставка обычного текста не перехватывается: если файлов в буфере нет,
обработчик выходит без `preventDefault`. Поле `readOnly`/офлайн — тоже выход.

Обработчик висит на контейнере, а не на `<textarea>`: `Ctrl+V` срабатывает и когда
фокус на кнопке внутри композера (событие всплывает).

## Рантайм панелей: OMP Pocket без herdr (2026-10-25)

**Почему.** Панели агентов (PTY, экран, ввод) держал herdr — отдельный процесс на
3 ГБ RSS и 2000+ задач, а связь «панель ↔ агент» восстанавливалась догадкой: сначала
по cwd, потом по pid из `pane process-info`. Ошибка в этой догадке означала ввод
клавиш (и `esc` = rewind) в чужую сессию. Плюс рестарт herdr гасил панели, а его CLI
был нужен даже для чтения экрана.

**Что появилось.** `gateway/runtime/` — свой демон панелей (юнит
`omp-pocket-runtime.service`, `bun gateway/runtime/main.ts`):

- панель — настоящий PTY с интерактивным bash; агент запускается *внутрь* панели
  (`pane.run` печатает одну экранированную команду в свободную оболочку), поэтому
  выход omp не убивает панель, а в неё же запускается восстановление;
- экран эмулируется `@xterm/headless` + `@xterm/addon-serialize`: приложение
  получает либо видимый текст, либо ANSI-снимок со скроллбеком;
- состояние — `panes.json` в `~/.local/state/omp-pocket/runtime/` (tmp + fsync +
  rename), у каждой записи `sessionId/instanceId/sessionFile/launchArgv`;
- связь шлюза и демона — unix-сокет 0600 с построчным JSON-RPC: `pane.list/create/
  get/run/read/input/resize/rename/bind/close/processInfo`, `health` и подписка
  `pane.attach` (сначала `snapshot` со `seq`, дальше только `seq+1` — разрыв
  нумерации означает «взять свежий снапшот»).

**Что это даёт.** Рестарт шлюза больше не трогает агентов (панели живут в другом
процессе). Рестарт рантайма поднимает панели из `panes.json` и возвращает агентов
тем же селектором сессии: `--restore`, а для панели, ждавшей подтверждения, —
`--resume` (турн за спиной человека не доигрывается). Панель, поднятая после
рестарта, помечается `restoredAt`, и шлюз (`gateway/recovery/runtimeWatch.ts`) один
раз досылает продолжение турна, после чего метку снимает.

**Границы.** herdr не удалён и не выключен: `herdr-server.service` и
`herdr-mobile-relay.service` продолжают работать для второго мобильного клиента
(свой протокол и свой релей). OMP Pocket их больше не вызывает — `grep -r herdr
gateway/` не находит обращений к его CLI. Агенты, поднятые в старых панелях herdr,
остаются в списке (реестр collab общий), но управляются из приложения только после
перезапуска в рантайме: «Остановить» и затем «Продолжить» — сессия поднимется уже
в панели рантайма.

**Эксплуатация.** `systemctl --user restart omp-pocket-runtime` (панели поднимутся
сами), состояние — `~/.local/state/omp-pocket/runtime/panes.json`, проверка —
`runtimeHealth()` в шлюзе (даёт pid, поколение и число панелей) и тесты
`bun test gateway/runtime/tests/`.
